# 영상별 회고 기록

`/shorts review`(또는 "회고하자")의 제작 회고와 눈길 지표 회고를 영상마다 쌓는 원본 기록이다. 평소에는 읽지 않는다. 그릴링 시리즈 편집자가 이번 주제와 같거나 비슷한 주제를 [summary.md](summary.md)에서 찾았을 때만, 그 영상 이름이나 주제 낱말로 검색해 그 제목 아래만 읽는다.

이 파일 전에 만든 영상(spring-lazy, thymeleaf, proxy, spring-bean)의 의견은 `docs/agents/planning-feedback.md`(기획)와 `doodles/rules.md`(그림·썸네일)에 영상 이름 제목으로 있다. 여기서 검색이 비면 거기서 같은 영상 이름을 찾는다.

## 형식

영상마다 제목 하나를 두고 아래 줄을 채운다. 새 영상은 맨 아래에 더한다. 교훈을 규칙으로 올리면 그 줄 끝에 "→ <올린 곳>으로 올림"을 붙인다.

```markdown
### <회고 날짜> <영상 이름> — <주제>
- 숫자: 기획안 n판(러프 n차, 곡 n번) · 미리보기 의견 n개 · 사용자가 먼저 잡은 문제 n개 · 길이 예상 m:ss → 실제 m:ss · 작업 시간 n분
- 좋았던 것:
- 아쉬웠던 것:
- 오래 걸린 수정: (어느 단계, 몇 판)
- 다음에 바꿀 것: (한 가지)
- 배운 점: [기획|그림|검토|제작] (summary.md 교훈 후보 한 줄)
- 그릴링: 기획안에 그대로 쓰인 답 / 헛돈 질문 (그릴링을 한 영상만)
- 지표 <날짜>: 조회수 n · 스와이프 안 함 n% · 평균 시청률 n% — 다음부터 한 줄 (눈길 지표 회고 뒤)
```

## 기록

### 2026-11-10 spring-bean-shorts — 텅 빈 빈을 사용해야 할 순간
- 숫자(승인 줄 전이라 어림): 기획안 4차에 승인(대본 5판, 러프 4차, 곡 3번) · 낙서 스토리보드 건너뜀(바로 Studio 미리보기) · 미리보기 의견 약 13개(대사·사실 8, 음악 이음매 2, 자막 싱크 2, 화면 글자 1) · 다시 녹음 3번 이상(계획 1번) · 사용자가 먼저 잡은 문제 5개(0:30 자막 싱크, 0:38 연결선 겹침, 0:39 이름표, 1:08·1:16 이음매) · 길이 예상 1:53 → 실제 2:14
- 좋았던 것: 나레이션과 배경음악이 잘 어울려 보기 편했다.
- 아쉬웠던 것: 0:38 빈에서 사람 셋으로 잇는 선이 앞뒤 없이 겹쳐 어색했다. 가장 큰 문제는 내용: 설명하고 싶은 게 많아 흩어져서, 빈이 결국 뭘 하는지 머리에 남지 않고 의문만 남았고, 그래서 남길 문장이 와닿지 않았다. "그림은 어설퍼도 내용의 진짜(지혜)가 그림을 뚫고 나와야 하는데, 지금은 그러지 못한다."
- 오래 걸린 수정: 음악 이음매(1:08, 1:16), 자막·나레이션(0:30 싱크, 대사 고침, 다시 녹음), 주인공 사물 러프 4차, 내용 보강(더 알차게 넣으려고 계속 바꿨지만 결국 못 함)
- 다음에 바꿀 것: 명확한 하나의 지혜가 드러나게 하기
- 배운 점: [기획] 고칠수록 내용을 더해 '왜'가 흩어졌다. 기획안 전에 그 개념이 하는 일을 한 문장('왜' 하나)으로 굳히고, 거기 닿지 않는 장면·문장은 뺀다. 의견으로 내용을 더할 때는 같은 만큼 덜어낸다. 그 '왜'는 현직 개발자도 끄덕일 깊이로(사용자) → 제작 기본값 "전달", start S5 현직 개발자 점검, grill G3로 올림. [그림] 여러 대상으로 잇는 선은 앞뒤와 흰 틈을 정한다 → 점검표 "그림"으로 올림
- 그릴링: 없음(그릴링을 넣기 전 영상)

### 2026-11-11 transaction-shorts — 트랜잭션은 실패를 없던 일로 만들 수 있을까?
- 숫자: 기획안 13판(러프 2차, 곡 1번 → 승인 뒤 곡 7번 더 바꿈) · 낙서 스토리보드 2판(그 사이 화풍·캐릭터 시안 5차, 주인공 사물 필름 릴 → 클래퍼보드) · 미리보기 의견 약 17개(1차 5, 추가 5, 2차 4, 깜빡임 3) · 렉 1번(펜 점 과다) · 게시 정보 1판 · 길이 예상 1:54 → 실제 1:52
- 걸린 시간: 약 7시간 40분(11-10 20:16 → 11-11 03:55, 세션 기록 기준), 목표 1시간의 7.7배. 속도 장부는 7단계 직전에야 켜져 16분만 기록됨.
- 좋았던 것: 없음(사용자: "오늘은 좋았던 점 하나도 없고").
- 아쉬웠던 것: "그냥 처음부터 끝까지 너무 오래 걸렸어". 한 단계가 아니라 기획·곡·그림·미리보기·렌더 모두에서 판이 늘고 기다림이 생겼다.
- 오래 걸린 수정 (큰 순서, 어림):
  1. 기획안 13판 약 2시간 반: 필요 장면 예시를 판마다 하나씩 바꿈(여행 예약 → 이직 → 로켓 → 시간 → 만 원 보내기 → 영화 촬영). 5판에서야 후보를 나란히 냄.
  2. 곡 약 2시간: 기준이 승인 뒤 세 번 바뀜(타격점 맞추기 → 차분·진중 → 주제와 곡의 짜임). 베토벤 이음매 4판 → 하바네라·투우사·윌리엄 텔·짐노페디 → 사탕요정의 춤. 곡을 하나씩 대본 길이에 맞춘 뒤 들려줌.
  3. 그림 약 1시간 반: 스토리보드 1판 퀄리티로 전부 다시 → 화풍 시안 2차 → 캐릭터 시안 → 사물 자체를 바꿈 → 클래퍼보드 시안. 기획안 러프에서 사물만 고르고 성격·화풍은 고르지 않았던 탓.
  4. 렉과 미리보기 약 1시간 반: 빗금 낙서가 펜 점 1.6만으로 렉 → 채움 면 도구를 새로 만듦. 미리보기 의견 약 17개가 장면별 바로 보이기 없이 끝에 몰림. 깜빡임을 세 번 고침(눈으로 찾음).
  5. 최종 렌더 약 10분(로그 593초): delivery 3354프레임을 전체 검사(브라우저 3개)·snapshot과 동시에 돌려 메모리가 모자라 느린 스크린샷 캡처로 떨어짐(로그 'too little memory'). 5분 알람이 울렸는데 FIX 줄이 이미 하던 것이라 '적용됨'으로 넘겨 사용자가 먼저 짚음 → FIX가 이미 적용된 상태면 '맞는 해결 없음'으로 보고 로그에서 원인을 찾는다. pace.py FIX "렌더"로 올림
